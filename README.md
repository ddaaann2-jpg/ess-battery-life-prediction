# ESS 배터리 수명 예측

ESS(전력망 배터리)의 교체 시점을 사전에 계획하기 위해, **초기 100 사이클 데이터만으로 배터리의 총 수명(`cycle_life`)을 예측**한다.
배터리 교체 비용은 ESS CAPEX의 30–40%를 차지하므로, 수명을 미리 알면 교체 시점 계획과 제조 직후 불량 셀 선별이 가능하다.

## 프로젝트 개요

- 데이터셋 : MIT-Stanford Battery Dataset (Severson et al., Nature Energy 2019)
- 학습 데이터 : Batch 1 (2017-05-12)
- 평가 데이터 : Batch 2 (2018-02-20)
- 태스크 : **Regression** (Cycle Life 예측, 타깃 log10 cycle_life, 지표 MAPE)
- 분할 : 프로토콜 단위 Hold-out (같은 충전 프로토콜 셀이 train/valid로 갈리는 누수를 막기 위함)

> ⚠️ **논문과의 비교 조건이 다르다.** 논문의 Batch 2는 2017-06-30 파일이고, 논문의 학습/Primary test는 Batch 1과 그 배치를 합쳐 **홀짝으로 나눈** 셀이다
> (공식 코드 `LoadData.m` / `Load Data.ipynb`의 `train_ind`/`test_ind`). 과제 지정 Batch 2(2018-02-20)는 논문 배치에 없다.
> 따라서 논문 9.1%와의 Gap(Target−Test)은 **같은 조건의 달성 목표가 아닌 참고 지표**로 해석한다.

## 핵심 결과

| 구분 | 모델 1 (선택: 피처 세트 C + 선형 회귀) | 모델 2 (ΔQ 전용: 피처 세트 B + 선형 회귀) | 비고 |
|---|---|---|---|
| Train (Batch 1 CV) | 7.0 | 7.8 | 프로토콜 단위 GroupKFold(5) out-of-fold |
| Valid (Batch 1 Hold-out) | 7.6 | 8.0 | 프로토콜 단위 Hold-out (시드 42) |
| Valid 반복 Hold-out 30회 평균 ± 표준편차 | 6.97 ± 1.26 | 7.80 ± 1.88 | 시드를 바꿔 반복 (공식 시드 42의 Valid와의 차이는 이 편차 안) |
| **Test (Batch 2)** | **40.8** | **27.7** | 39셀, 최종 모델 1회 평가 |
| Gap (Train-Valid) | 0.6 | 0.2 | (+): 과적합 의심 |
| Gap (Valid-Test) | 33.2 | 19.7 | (+): 배치 간 일반화 저하 |
| Gap (Target-Test) | 31.7 | 18.6 | Target: 원논문 9.1% (비교 조건이 달라 참고) |
| ↳ Test: B2 일반 30셀 | 46.7 | 29.2 | 기존 구조 셀 |
| ↳ Test: B2 newstructure 9셀 | 21.2 | 22.6 | |

지표는 MAPE(%)이며 Gap은 (+)가 나쁜 방향이다 (`Valid−Train`, `Test−Valid`, `Test−9.1`).

주의: Valid는 모델 선택에 쓴 **같은 36셀 풀**에서 나온 Hold-out이라 약간 낙관적이다. Train CV는 scikit-learn 버전에 따라 GroupKFold 폴드 배정이 달라져 소수점 첫째 자리가 바뀔 수 있다 (1.9.1 기준 7.0 / 7.8, 외부 환경(1.8.0)에서 6.8 / 8.4가 재현된 사례가 있다). Valid·Test는 같은 값이 재현된다.

**한 줄 요약** 배터리 **안**(Batch 1)에서는 7–8%로 잘 맞히지만, **다른 배치**(Batch 2)로 가면 크게 무너진다 (27.7–40.8%).
원인은 모델이 아니라 **배치 간 이동** — 같은 충전 프로토콜(4.8C(80%)-4.8C)의 수명이 B1 753, B2 484로 다르다. B1 내부 검증으로는 이를 감지할 수 없다.
피처를 하나씩 더하고 빼 보니 B2 악화는 **초기 용량 피처 하나**에서 나왔다 ([원인 분해](#원인-분해-초기-용량-피처)): B1 Valid는 좋아지는데 B2는 나빠졌다.

## 논문 성능과의 비교

논문의 보고 성능(Regression 9.1%)과 이 결과는 **같은 질문에 대한 답이 아니다.** 어디까지 비교할 수 있는지 조건부터 확인했다.

| | 논문 (공식 코드 `LoadData.m` / `Load Data.ipynb`) | 이 과제 |
|---|---|---|
| 데이터 | B1(2017-05-12) + 논문 B2(**2017-06-30**) → 학습 41 / primary test 43, 별도 secondary test | B1 학습 → 과제 B2(**2018-02-20**) 테스트 |
| 분할 | B1·논문 B2를 합쳐 **셀 순서대로 홀짝** 분할 | **프로토콜 단위** Hold-out / GroupKFold |

**직접 계산** B1 41셀을 논문 방식(홀짝)으로 나누면 test 셀 21개 중 **19개(90%)가 같은 프로토콜의 쌍둥이 셀을 train에 갖고 있고**,
2셀 이상인 프로토콜 18개가 전부 train·test 양쪽에 걸친다. 프로토콜 단위 분할에서는 0%다.
같은 프로토콜 셀은 수명이 비슷하므로(프로토콜 내 CV 6–7% vs 간 23–40%) 이 분할은 쉬운 문제를 만든다.

**해석**
- 같은 배치 안(B1 Hold-out) 7.6–8.0%는 더 엄격한 분할인데도 논문의 9.1%와 같은 자릿수다 → 파이프라인이 크게 어긋난 정황은 아니다. (이 비교도 조건이 같지는 않다.)
- 다른 배치(B2)로 가면 27.7–40.8%로 나빠진다. 논문의 홀짝 분할 설계에서는 이런 배치 간 이동이 드러나기 어렵다.
- **시사점: 성능 숫자는 평가 설계가 정한다.** 9.1%는 "같은 배치·같은 프로토콜 계열 안에서의 예측"에 가깝고, 이 과제의 B2는 "새 배치에서의 예측"이다.
  ESS 현장에서 궁금한 것(새 셀 로트의 수명)은 후자에 가깝다.
- 한계: 논문의 B2 파일이 없어서 "분할 방식의 효과"와 "배치 효과"를 분리해 확인하지는 못했다. Batch 3는 가이드에 따라 평가하지 않았다.

## Modeling

### 피처 엔지니어링 전략

초기 사이클(2–100)에서 셀 단위 피처를 만든다 (`src/features.py`, `notebooks/02_feature_engineering.ipynb`).
핵심은 **`log10 Var[ΔQ(V)]`** — 전압 구간별 용량 변화의 분산으로, EDA에서 세 배치 모두 수명과 같은 방향(−0.71–−0.88)이었다.

| 세트 | 구성 | 근거 |
|---|---|---|
| A | `log Var[ΔQ]` | 핵심 피처 1개 |
| B | ΔQ 통계 3종 (Var, min, mean) | 같은 계열이라 상관 0.98–0.99 → 규제 모델로 처리 |
| C | A + QD 기울기(91–100), 전환 SOC, Tmax, ΔQ 첨도, 초기 용량 | Day 1 EDA에서 고른 보조 피처 (B2·B3 EDA를 참고했다는 한계) |
| D | 전체 후보 15개 | 다중공선성 확인용 |
| E | **학습 데이터 내부**에서 프로토콜 서브샘플링으로 부호가 안정적인 피처만 선별 | C의 한계를 보완 (매 분할 안에서 새로 선별해 검증 셀이 섞이지 않음) |

제외: 평균 C-rate·충전시간(B2에서 반전), ΔQ 왜도·QD 기울기(2–100)(B1에서만 유의), IR 계열(약함, 6셀 결측).
전처리(log10 변환, 표준화, 결측 대체)는 모두 학습 데이터에서만 계산한다.

### 모델 선택 및 근거

- 후보 모델 : 선형 회귀, Elastic Net, Random Forest, Gradient Boosting, LightGBM (딥러닝은 학습 셀 36개라 제외)
- 후보 25개 = 피처 세트 5개 × 모델 5개. **Batch 1의 프로토콜 단위 Hold-out을 시드를 바꿔 30회 반복**해 평균 MAPE로 비교한다.
  하이퍼파라미터 탐색도 학습 데이터 안의 프로토콜 GroupKFold로만 한다.
- 선택 규칙 : 최고 성능의 1 표준오차 이내인 후보 중 가장 단순한 것 (피처 수 → 모델 복잡도).
- **Batch 2는 모델 선택에 사용하지 않는다.** 선택된 모델을 B1 36셀 전체로 재학습해 B2에 1회 평가한다.
- 최종 모델 :
  - **모델 1 = 피처 세트 C + 선형 회귀**: 1 표준오차 규칙으로 선택. 반복 Hold-out 최고는 C + Elastic Net(6.78 ± 1.10%)이고, C + 선형 회귀(6.97 ± 1.26%)는 최고 + 표준오차(0.20) 이내(≤ 6.98)에서 더 단순해 뽑혔다.
  - **모델 2 = 피처 세트 B + 선형 회귀**(7.80 ± 1.88%): Day 1에서 먼저 정한 "ΔQ 핵심 피처(A·B)로 시작" 전략 안에서 같은 규칙으로 선택.
- 선택 이유 : 표본이 작고(36셀) 피처 간 상관이 높아 단순한 선형 모델이 B1 안에서 가장 안정적이었다.

### 성능 결과

위 [핵심 결과](#핵심-결과) 표 참고. 분할 구조는 `results/figures/m1_split_protocols.png`.

- **Gap (Train-Valid) ≈ 0.2–0.6%p** — B1 안에서는 과적합이 거의 없다 (프로토콜 단위로 분리했는데도 Valid가 Train과 같은 수준).
- **Gap (Valid-Test) +20–33%p** — B1 안에서 7–8%인 모델이 B2에서 28–41%가 된다. 배치 간 일반화 문제다.
- **Gap (Target-Test) +19–32%p** — 논문 9.1%에 미치지 못하지만, 논문은 B1과 논문 B2를 홀짝 분할한 셀로 평가했으므로 같은 조건의 목표가 아니다.

![후보 비교](results/figures/m2_candidates_b1_vs_b2.png)

**핵심 발견: B1 내부 검증은 배치 이동을 감지하지 못한다.** B1 Hold-out이 더 좋다고 한 모델 1(세트 C)은 B2에서 ΔQ 전용 모델 2보다 오히려 나쁘다.
(B2 열은 선택 후 참고용으로만 계산했다 — `results/candidates_b2_reference.csv`.)
B1 안에서 수명이 가장 짧은 프로토콜을 빼고 학습하는 외삽 검증도 해봤지만 세트 C가 오히려 가장 좋았다(`results/shift_check_b1.csv`) → 수명 범위의 외삽 때문이 아니다.

#### 원인 분해: 초기 용량 피처

세트 C가 왜 B2에서 무너지는지, 피처를 하나씩 더하고 빼며 확인했다 (36셀, 선형 회귀, Hold-out 시드 42, 단위 MAPE %).

| 구성 | B1 Valid | B2 전체 | B2 일반 | B2 new |
|---|---|---|---|---|
| A (Var만) | 10.4 | 28.6 | 31.9 | 17.5 |
| A + 초기 용량(qd_2) | 7.1 | 45.2 | 48.1 | 35.6 |
| A + 전환 SOC | 10.4 | 28.7 | 32.3 | 16.8 |
| A + Tmax | 10.8 | 28.6 | 32.0 | 17.4 |
| C 전체 | 7.6 | 40.8 | 46.7 | 21.2 |
| C − 초기 용량 | 11.3 | 28.8 | 32.6 | 15.9 |
| C − 전환 SOC | 7.6 | 41.0 | 46.8 | 21.7 |
| C − Tmax | 7.6 | 41.0 | 46.9 | 21.2 |

- **B2 악화는 초기 용량(`qd_2`) 하나에서 나온다.** A에 초기 용량만 더해도 B1 Valid는 10.4 → 7.1로 좋아지지만 B2는 28.6 → 45.2로 나빠진다. C에서 초기 용량만 빼면 B2가 40.8 → 28.8로 돌아온다.
- 전환 SOC와 Tmax는 B2에 영향이 없다 (더하거나 빼도 거의 같고, 표준화 계수도 −0.004, −0.002). 처음에는 "전환 SOC·Tmax 같은 프로토콜 계열 피처가 원인"이라고 추측했지만 이 실험으로 틀렸음을 확인했다.
- **이유 (확인함):** 초기 용량이 B1 학습 범위 밖으로 이동했다 (`results/initial_capacity_shift.csv`).
  - B2 일반 30셀의 초기 용량 평균 1.095Ah는 B1 학습 풀 평균(1.078)보다 B1 표준편차(0.0083)의 2.0배 높고, 30셀 중 17개가 B1 최댓값(1.095)을 넘는다.
  - A + 초기 용량 모델에서 B2 일반 셀의 초기 용량만 B1 평균으로 바꿔 예측하면 MAPE가 48.1% → 28.2%로 내려간다. 이동 효과가 정확히 이 피처에서 나온다.
  - B1 안에서 초기 용량과 log 수명의 단순 상관은 +0.16으로 약하지만, Var[ΔQ]를 통제한 편상관은 +0.69다. "초기 용량이 높을수록 수명이 길다"는 **B1 한정의 조건부 관계**였고, B2 일반 셀은 초기 용량이 높은데 수명은 짧아 과대 예측이 생긴다.
- 시사점: **B1 지표가 좋아지는 방향으로 피처를 더했는데 B2가 나빠진 것은 초기 용량의 배치 간 분포 이동 때문이다. 그 조건부 관계는 B1에서만 학습됐다.** B1 내부 검증의 한계를 가장 선명하게 보여주는 사례다.
- 주의: B2를 본 뒤에 하는 **사후 분석**이다. 모델 선택에는 쓰지 않았고(모델 1은 그대로) 해석에만 쓴다. (`src/analysis/feature_ablation.py`, `results/feature_ablation.csv`)

### 오류 분석

![B2 예측 vs 실제](results/figures/m3_b2_pred_vs_true.png)

모델이 가장 크게 틀린 셀의 공통점:

1. 상위 오차 셀은 **전부 B2 일반 셀**이고 실제 수명이 가장 짧은 구간(392–477)이다. 모델 1은 실제보다 65–100% 길게 예측한다.
2. 오차가 거의 한 방향(과대 예측)이다 → 무작위 노이즈가 아니라 **체계적 편향**이다 (MAPE ≈ 부호 있는 오차).
3. **ΔQ 분산은 학습 범위 안인데도 틀린다.** 상위 8개 중 6개는 `log Var[ΔQ]`가 학습 범위 안에 있고, B2 일반 30셀만 보면 범위 안 19개의 오차(52.1%)가 범위 밖 11개(37.5%)보다 크다 (39셀 전체 46.1%(22개) vs 34.0%(17개), 모델 1).
   그러나 이것은 피처 **한 개**만 본 것이다. 모델 1의 큰 오차는 **초기 용량이 B1 범위 밖으로 이동한 데서** 나왔다(원인 분해). 정리하면 "ΔQ 분산은 범위 안, 초기 용량은 범위 밖"인 **공변량 이동**이다.
   타깃도 다르다: 일반 30셀 수명(392–514)은 B1 최솟값(534) 밖이다.
4. newstructure 9셀은 두 모델 모두 21–23%로 상대적으로 낫다.

**원인 가설**(현 데이터로 검증 불가): 배치별 셀 로트·측정 조건 차이. 초기 용량 평균이 배치마다 다르다 (B1 학습 풀 1.078 / B2 일반 1.095Ah).

**개선 방향** (모두 검증하지 않은 가설): ① 초기 용량 절대값 피처를 빼거나 배치별로 재보정한다 (실험이 가리키는 쪽: C − 초기 용량 = B2 28.8%),
② 새 배치마다 소량의 참조 셀 레이블로 재보정한다, ③ ΔQ를 초기 용량으로 정규화한 피처를 시도한다 (미검증).

학습 라벨 처리 민감도(`results/sensitivity_labels.csv`): 36셀 기본, 원 라벨 41셀, 논문 코드의 `add_len`으로 보정한 41셀을 비교하면 B2 MAPE가 모델 1은 40.8 / 49.5 / 44.5%, 모델 2는 27.7 / 33.8 / 25.7%다.
집단마다 방향이 달라 어느 쪽이 항상 낫지는 않다. 36셀을 기본으로 한 이유는 외부 상수가 필요 없고 검열된(하한값) 라벨을 정확값처럼 쓰지 않기 때문이다. 단점은 학습 최대 수명이 1,074로 낮아진다는 점이다.

## ESS 도메인 해석

**어떤 의사결정에 쓸 수 있는가**
- *교체 시점 계획* — 초기 100 사이클의 ΔQ(V) 신호로 수명 규모를 가늠해 교체 CAPEX를 사전에 계획한다.
  같은 배치(같은 셀 로트) 안에서는 B1 Hold-out 수준(약 7–8%)의 정밀도를 기대할 수 있다.
- *제조 직후 불량 셀 선별* — `log Var[ΔQ]`가 큰 셀(수명이 짧을 가능성)을 초기에 걸러 팩 구성을 최적화한다.

**한계와 실 배포를 위한 추가 요건**
- **배치 간 일반화가 약하다.** 새 셀 로트가 들어오면 같은 ΔQ에서도 수명이 달라질 수 있다 (B2 일반 셀 과대 예측 +29–46%).
  실제 운영에서는 새 로트마다 소량의 보정 데이터(참조 셀 수명)로 **재보정**해야 한다.
- 학습 범위 밖 입력에는 **외삽 경고 플래그**를 단다 (`src/evaluate.py`의 `extrapolation_flag`, 결과는 `results/error_analysis_b2.csv`의 `extrapolation_m1/m2`, `var_out_of_range`). 플래그의 구분력은 모델마다 다르다 (`results/extrapolation_flag_check.csv`): 모델 1은 초기 용량이 B1 범위를 벗어나 39셀 중 38개에서 켜져 **구분 능력이 없고**, 모델 2는 켜진 셀의 오차(22.5%)가 꺼진 셀(31.7%)보다 오히려 작아 **플래그가 큰 오차를 가려내지 못한다.** 범위 이탈 플래그만으로는 충분하지 않다.
- 표본이 작다(36셀, 20개 프로토콜). 초기 용량 같은 **절대값 피처**는 셀 로트가 바뀌면 오히려 해가 될 수 있다 (B1 Valid는 좋아지는데 B2는 나빠졌다). 새 배치에서는 쓰기 전에 다시 검증해야 한다.
- 이 결과는 과제 지정 Batch 2 기준이며 논문 9.1%와 같은 조건의 비교가 아니다.

## 재현성 메모

- 모든 난수는 시드를 고정했다 (`src/config.py`, `src/split.py`). 반복 Hold-out 시드는 0–29, 공식 Hold-out 시드는 42이다.
- Hold-out은 프로토콜 5개를 무작위로 뽑되, 가장 짧은 수명 구간을 대표하는 `5.4C(80%)-5.4C`는 항상 Train에 둔다.
- 피처 선별(세트 C)에는 Day 1 EDA에서 B2·B3를 참고한 정보가 들어 있다. 세트 E는 이 한계를 줄이려고 학습 데이터 안에서만 선별한다.
- `add_len`(= [662, 981, 1060, 208, 482]) 상수는 논문 공식 저장소(`rdbraatz/data-driven-prediction-of-battery-cycle-life-before-capacity-degradation`)에서 가져왔다. `src/analysis/label_sensitivity.py`에 출처 확인 수준을 적어 두었다.

## 분석 과정 기록

만들면서 생각이 바뀐 지점을 순서대로 적어 둔다 (결과보다 과정이 남도록).

1. **분류 대신 회귀.** 수명 분포를 보니 550 기준으로 나누면 B1 학습 데이터의 단수명이 1개뿐이었다. 정확도가 높아 보여도 의미가 없다고 판단.
2. **내 예상이 틀린 첫 경험.** "학습 범위 밖은 선형 모델이 외삽에 유리할 것"이라고 썼지만 사전 점검에서는 Random Forest가 더 나았다. 가설을 폐기하고 측정값 기준으로 다시 썼다.
3. **라벨이 의심스러운 셀 발견.** B1 10셀이 EOL에 도달하지 않았는데 `cycle_life`가 채워져 있었다(기록 길이 + 1). 그래서 제외 5셀과 하한값 5셀을 구분했고, 학습은 관측 라벨만 쓰는 36셀로 정했다. 이 선택이 성능을 어느 쪽으로 움직이는지는 집단마다 달라서 아직 확신이 없다.
4. **논문 조건 확인.** 논문 코드를 열어 보니 논문의 Batch 2는 다른 파일이었고, 학습/테스트가 홀짝 분할이었다. 9.1%를 "달성 목표"로 두면 안 된다는 걸 알게 됐다.
5. **Day 1 피처 선별의 한계.** B2·B3 EDA를 본 뒤 고른 피처라 B2는 완전한 blind test가 아니다. 그래서 학습 데이터 안에서만 선별하는 세트 E를 만들었다.
6. **B1에서 7%, B2에서 40%.** 가장 의외였던 결과. Day 1에서는 "학습 범위 밖 외삽"이 원인이라고 생각했지만, 오차를 보니 범위 **안**에 있는 셀의 오차가 더 컸다. 같은 ΔQ 값에서도 B2 일반 셀의 수명이 B1보다 짧다 — 배치 이동이다.
7. **B1 안의 검증으로 감지할 수 있는가?** 가장 짧은 프로토콜을 빼고 학습하는 외삽 검증을 해봤지만 오히려 세트 C가 가장 좋았다. B1만 보는 한 이 이동은 안 보인다.

8. **원인 해석을 코드로 검증했더니 틀렸다.** B2에서 세트 C가 무너지는 이유를 처음에는 "전환 SOC·Tmax 같은 프로토콜 계열 피처" 때문이라고 설명했다. 피처를 하나씩 더하고 빼 보니 실제 원인은 초기 용량 하나였다. 그럴듯한 설명을 실험으로 확인하지 않은 채 쓴 문장이었다. 이 설명도 한 번 더 고쳤다. 처음에는 "같은 ΔQ·초기 용량 조합에서 B2 셀의 수명이 더 짧다"고 썼지만 B1에는 그런 조합이 없는 셀이 많아 정확하지 않았다. 정확한 표현은 "초기 용량이 B1 학습 범위를 벗어나는 공변량 이동"이었다. 외삽 플래그도 모델 1에서는 거의 항상 켜져 의미가 없다는 걸 나중에야 확인했다.

**아직 모르는 것**: 이동의 원인(셀 로트·측정 조건 가설은 검증할 방법이 없다), 36셀과 add_len 보정 중 어느 라벨 처리가 맞는지, 홀짝 분할의 효과와 배치 효과를 분리하는 방법.
